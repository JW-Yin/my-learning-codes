# SUID、SGID、SBIT 权限详解
这三个是Linux系统中，基于基础`rwx`（读/写/执行）权限的**特殊权限位**，用于解决基础权限无法覆盖的场景，核心是对「执行/目录操作」做权限扩展。

---

## 一、前置基础
Linux文件权限默认分为3组，对应3类用户：
```
属主权限(u)  属组权限(g)  其他用户权限(o)
 r w x        r w x        r w x
```
SUID、SGID、SBIT分别对应这3组的**扩展位**，有两种表示方式：
- 符号表示：在对应组的`x`位上显示`s/S`（SUID/SGID）、`t/T`（SBIT）
- 数字表示：在基础3位权限前加1位特殊权限位，`SUID=4`、`SGID=2`、`SBIT=1`，可叠加（如`4+2=6`代表同时设置SUID+SGID）

---

## 二、SUID（Set User ID，设置用户ID）
### 核心作用
让**执行该二进制程序的用户，临时获得程序「属主」的权限**（而非执行者自身的权限），权限仅在程序运行期间有效，程序结束即收回。

### 生效条件（缺一不可）
1.  仅对**二进制可执行文件**生效（Shell/Python等脚本无效，内核会优先执行解释器，忽略脚本的SUID）
2.  执行者对该文件拥有`x`（执行）权限
3.  仅在程序运行生命周期内生效

### 权限标识
- 符号：在**属主的x位**，有x权限显示小写`s`，无x权限显示大写`S`（无效SUID）
- 数字：权限前缀为`4`，例如`4755`（SUID + 基础755权限）

### 经典示例
最典型的是`/usr/bin/passwd`命令：
```bash
$ ls -l /usr/bin/passwd
-rwsr-xr-x 1 root root 59976 Jan 10  2024 /usr/bin/passwd
```
- 普通用户修改密码，需要修改只有root能写的`/etc/shadow`文件
- 靠passwd的SUID权限，普通用户执行时临时获得root权限，完成密码修改

### 常用操作
```bash
# 设置SUID
chmod u+s 文件名
chmod 4755 文件名

# 取消SUID
chmod u-s 文件名
chmod 755 文件名
```

### 关键注意事项
**SUID是高危权限**：给root属主的二进制文件设置SUID，极易被用于权限提升（例如给`/bin/bash`加SUID，普通用户执行即可直接获得root权限），生产环境严禁随意设置。

---

## 三、SGID（Set Group ID，设置组ID）
SGID有两个完全独立的生效场景，分别针对文件和目录，其中目录场景更常用。

### 1. 针对二进制可执行文件
#### 核心作用
和SUID逻辑一致：让执行程序的用户，临时获得程序**「属组」的权限**，仅在程序运行期间有效。
#### 生效条件
与SUID完全一致：仅对二进制可执行文件生效、执行者有x权限、运行期有效。
#### 权限标识
- 符号：在**属组的x位**，有x权限显示小写`s`，无x权限显示大写`S`（无效SGID）
- 数字：权限前缀为`2`，例如`2755`

### 2. 针对目录（核心常用场景）
#### 核心作用
在设置了SGID的目录中，**新建的文件/子目录，会自动继承该目录的属组**，而非继承新建者的默认主组。
#### 典型用途
团队协作共享目录：比如多个用户同属一个开发组，在共享目录中新建文件时，自动继承共享目录的属组，无需手动执行`chgrp`修改组权限，避免跨用户无法访问的问题。

### 实操示例（共享目录）
```bash
# 1. 创建共享组和共享目录
groupadd devteam
mkdir /srv/dev_share

# 2. 设置目录属组，添加SGID权限
chown root:devteam /srv/dev_share
chmod 2770 /srv/dev_share  # 2=SGID，770=属主属组全权限，其他用户无权限

# 3. 效果：组内用户新建文件，自动继承devteam属组
su - user1  # user1属于devteam组
touch /srv/dev_share/test.txt
ls -l /srv/dev_share/test.txt
# 输出：-rw-rw---- 1 user1 devteam 0 Mar  8 15:00 test.txt
```

### 常用操作
```bash
# 设置SGID
chmod g+s 文件/目录
chmod 2770 目录

# 取消SGID
chmod g-s 文件/目录
chmod 770 目录
```

## 四、SBIT（Sticky Bit，粘滞位）
### 核心作用
**仅对目录生效**（对普通文件的用法已被现代Linux淘汰）：
在设置了SBIT的目录中，**只有文件/子目录的属主、root用户，才能删除、移动、重命名该文件**；哪怕其他用户对该目录拥有`w`（写）权限，也无法操作别人的文件。

### 经典示例
系统临时目录`/tmp`，所有人都有rwx权限，但无法删除别人的文件：
```bash
$ ls -ld /tmp
drwxrwxrwt 16 root root 4096 Mar  8 14:00 /tmp
```
- 权限末尾的`t`就是SBIT标识，`1777`是完整权限（1=SBIT + 777基础权限）

### 权限标识
- 符号：在**其他用户的x位**，有x权限显示小写`t`，无x权限显示大写`T`（无效SBIT）
- 数字：权限前缀为`1`，例如`1777`

### 常用操作
```bash
# 设置SBIT
chmod o+t 目录
chmod 1777 目录

# 取消SBIT
chmod o-t 目录
chmod 777 目录
```

## 五、核心对比速查表
| 权限 | 全称 | 数字代号 | 生效位置 | 核心作用 | 典型场景 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| SUID | Set User ID | 4 | 属主x位 | 执行程序时临时获得文件属主权限 | passwd命令、sudo命令 |
| SGID | Set Group ID | 2 | 属组x位 | 1. 执行程序时临时获得文件属组权限<br>2. 目录内新建文件自动继承目录属组 | 团队共享目录、locate命令 |
| SBIT | Sticky Bit | 1 | 其他用户x位 | 目录内仅文件属主/root可删除文件 | /tmp、/var/tmp公共临时目录 |

---

## 六、关键补充与常见误区
1.  **大写S/T的含义**：代表特殊权限**无效**。比如给无x权限的文件加SUID，属主x位会显示`S`，因为没有执行权限，SUID无法生效，属于错误的权限设置。
2.  **SUID对脚本无效**：Shell、Python等脚本的SUID会被内核忽略，仅对编译后的二进制可执行文件生效。
3.  **权限继承规则**：SGID仅对**新建**的文件/目录生效，目录内已存在的文件不会自动继承属组。
4.  **高危权限排查**：生产环境需定期扫描系统中的SUID/SGID文件，排查风险：
    ```bash
    # 查找所有带SUID的文件
    find / -perm /4000 -type f 2>/dev/null
    # 查找所有带SGID的文件
    find / -perm /2000 -type f 2>/dev/null
    ```
