# free 命令完整学习指南
## 一、背景与定位
在 Linux 系统中，**实时监控内存和交换空间（Swap）的使用情况**是排查系统性能问题（如卡顿、OOM 进程被杀）的核心需求。`free` 就是解决这个问题的**轻量级、开箱即用的内存监控工具**。

- **核心作用**：快速查看系统总内存、已用内存、空闲内存、缓存/缓冲、交换空间的使用状态。
- **优势**：输出简洁、数据实时、无需额外安装，是性能排查的首选工具之一。

---

## 二、前置准备
Ubuntu 22.04 及绝大多数 Linux 发行版默认自带 `free` 命令，无需安装，直接执行即可使用。

---

## 三、基础语法
```bash
free [选项]
```
核心规则：所有参数均标注**英文全称**，方便理解记忆。

---

## 四、核心：默认输出完整解读
执行 `free` 命令（无参数）会输出默认格式的内存信息，这是新手最容易困惑的部分，我们逐段逐字段拆解：
```
               total        used        free      shared  buff/cache   available
Mem:        16302384     3210456     8765432      210987     4326496    12567890
Swap:        2097148           0     2097148
```

### 字段详解表（按输出顺序）
| 字段 | 英文全称 | 核心含义 | 通俗易懂的解释 |
|------|----------|----------|----------------|
| **total** | Total | 总内存/总交换空间大小 | 系统物理内存或 Swap 分区的总容量 |
| **used** | Used | 已使用的内存/交换空间大小 | 真正被进程占用的内存（不包含缓存/缓冲） |
| **free** | Free | 完全空闲的内存/交换空间大小 | 完全没被使用的内存，**注意：这不是真正可用的内存** |
| **shared** | Shared | 共享内存大小 | 主要被 tmpfs（临时文件系统）和进程间共享内存占用 |
| **buff/cache** | Buffers + Cache | 缓冲区 + 缓存大小 | 系统为了提高性能预留的内存：<br>- **Buffers**：缓存磁盘元数据（如 inode、目录结构）和块设备的临时写入<br>- **Cache**：缓存文件系统的文件内容，下次读取直接从内存取，速度极快 |
| **available** | Available | 真正可用的内存大小 | 这是**最核心的字段**！表示系统可以立即分配给新进程的内存，包含 `free` 和可回收的 `buff/cache` |

### 行详解
| 行 | 核心含义 |
|----|----------|
| **Mem** | 物理内存（RAM）的使用情况 |
| **Swap** | 交换空间（虚拟内存，用磁盘模拟内存）的使用情况 |

## 五、高频常用参数与实战
### （一）格式化输出类（新手必用，提升可读性）
| 参数 | 英文全称 | 用途 | 示例 |
|------|----------|------|------|
| `-h` | `--human-readable` | **自动格式化输出**（根据大小自动选择 KB/MB/GB/TB，最常用） | `free -h` |
| `-m` | `--mega` | 强制以 **MB** 为单位输出 | `free -m` |
| `-g` | `--giga` | 强制以 **GB** 为单位输出 | `free -g` |
| `-k` | `--kilo` | 强制以 **KB** 为单位输出（默认单位） | `free -k` |

#### 实战示例：`free -h`（最常用的格式化输出）
```
               total        used        free      shared  buff/cache   available
Mem:            15Gi       3.0Gi       8.3Gi       205Mi       4.1Gi        12Gi
Swap:          2.0Gi          0B       2.0Gi
```
输出直观易懂，一眼就能看懂内存使用情况。

---

### （二）持续监控类（性能排查必备）
| 参数 | 英文全称 | 用途 | 示例 |
|------|----------|------|------|
| `-s N` | `--seconds N` | 每隔 **N 秒**刷新一次输出（持续监控） | `free -h -s 2`（每隔 2 秒刷新一次） |
| `-c N` | `--count N` | 配合 `-s` 使用，**只刷新 N 次**后自动退出 | `free -h -s 2 -c 5`（每隔 2 秒刷新，共刷新 5 次） |

#### 实战示例：持续监控内存变化
```bash
# 每隔 1 秒刷新一次，共刷新 10 次，自动退出
free -h -s 1 -c 10
```
适合观察进程启动/运行时的内存变化。

---

### （三）其他实用类
| 参数 | 英文全称 | 用途 | 示例 |
|------|----------|------|------|
| `-t` | `--total` | 在输出底部增加一行 **总计**（物理内存 + 交换空间的总和） | `free -h -t` |
| `-w` | `--wide` | **宽格式输出**（将 `buff/cache` 拆分为单独的 `buffers` 和 `cache` 列） | `free -h -w` |

#### 实战示例：宽格式输出（拆分 buff/cache）
```
               total        used        free      shared     buffers       cache   available
Mem:            15Gi       3.0Gi       8.3Gi       205Mi       1.2Gi       2.9Gi        12Gi
Swap:          2.0Gi          0B       2.0Gi
```
可以单独查看 `buffers` 和 `cache` 的使用情况。

## 六、避坑指南（高频核心误区）
1. **不要混淆 `free` 和 `available`**：
   - `free` 是完全空闲的内存，数值小很正常，因为系统会把空闲内存用作 `buff/cache` 提高性能。
   - `available` 才是真正可用的内存，只要 `available` 足够大，系统就不会卡顿。

2. **`buff/cache` 不是“浪费内存”**：
   - 这是 Linux 系统的核心优化机制：空闲内存不用白不用，用作缓存可以大幅提升磁盘读写速度。
   - 当新进程需要内存时，系统会自动回收可回收的 `buff/cache` 分配给新进程，无需手动清理。

3. **Swap 使用率高不代表系统性能差**：
   - Swap 是虚拟内存，当物理内存不足时，系统会把不常用的内存页换出到 Swap。
   - 但如果 Swap 持续高频率读写（可用 `vmstat` 查看 `si`/`so` 字段），说明物理内存严重不足，需要优化进程或增加物理内存。

## 七、学习路径建议
1. **入门**：先练熟 `free -h` 看懂格式化输出，重点理解 `available` 和 `buff/cache` 的含义。
2. **进阶**：掌握 `free -h -s N -c N` 持续监控内存变化，配合 `top`/`htop` 一起排查性能问题。
3. **精通**：结合 `vmstat`、`sar` 等工具，深入分析内存的换入换出、缓存命中率等细节。
4. 常用：`free -wth -s 1 -c 5`
