## 2025-1

- ACID 特性  
原子性：事务要么全执行，要么全不执行，无中间状态；  
一致性：事务执行前后数据库满足完整性约束，状态合法；  
隔离性：多事务并发执行互不干扰，避免并发异常；  
持久性：已提交事务的修改永久有效，不因故障丢失。  
- 作用  
并发控制：隔离性为核心，通过并发控制机制（锁 / 多版本）保证隔离性，避免脏读、不可重复读等并发异常，最终实现并发下的一致性；  
故障恢复：原子性通过undo log实现未提交事务的回滚，持久性通过redo log实现已提交事务的修改持久化，二者共同保障故障后数据库能恢复到一致的合法状态，一致性是故障恢复的最终目标。

1.  **外模式**：用户可见的局部逻辑视图（对应视图）；
2.  **模式**：数据库全局逻辑结构（对应基本表）；
3.  **内模式**：数据底层物理存储结构（对应存储文件、索引）。

通过**两层映射**实现**数据独立性**：
1.  **外模式-模式映射**：保证**逻辑独立性**——全局逻辑结构改变，用户视图和应用程序不变；
2.  **内模式-模式映射**：保证**物理独立性**——底层存储结构改变，全局逻辑和用户视图不变。

- 模式、内模式：**各1个**；
- 外模式：**可多个**。

## 2019-1

并发调度正确性的标准并发调度正确性的唯一核心准则是可串行化（可串行性）：若多个事务的并发调度执行结果，与这些事务按某一任意串行顺序依次执行的结果完全等价，则该调度是正确的。冲突可串行化是工程中可高效判定的、可串行化的充分非必要条件。

保证并发调度正确性的方法核心是通过并发控制机制，确保调度满足可串行化准则：  
① 核心方案：遵守两段锁协议（2PL），该协议是保证冲突可串行化的充分条件，将事务严格分为「加锁阶段（仅申请锁，不释放锁）」和「解锁阶段（仅释放锁，不申请锁）」，工程中普遍使用严格两段锁协议，兼顾正确性与故障安全性；  
② 补充方案：可采用时间戳排序协议、乐观并发控制协议，从事务时序 / 提交验证维度保证调度可串行化；  
③ 辅助保障：设置串行化事务隔离级别、规范事务设计（缩小粒度、避免长事务）等。

## 2019-2

### 分步计算过程

#### 第一步：计算自然连接 \( R \bowtie S \)
自然连接的核心规则：保留关系 \( R \) 和 \( S \) 中**公共属性（B、C）值完全相等**的元组，合并属性后去重。

匹配过程如下：
- \( R \) 中第1行 (1, a, 2)：S中无 (B=a, C=2) 的元组，舍弃；
- \( R \) 中第2行 (4, b, 2)：与S中 (b, 2) 匹配，保留；
- \( R \) 中第3行 (2, c, 3)：与S中 (c, 3) 匹配，保留；
- \( R \) 中第4行 (3, e, 3)：与S中 (e, 3) 匹配，保留；
- \( R \) 中第5行 (2, e, 3)：与S中 (e, 3) 匹配，保留。

因此，$( R \bowtie S )$ 的结果为：

| A   | B   | C   |     |
| --- | --- | --- | --- |
| 4   | b   | 2   |     |
| 2   | c   | 3   |     |
| 3   | e   | 3   |     |
| 2   | e   | 3   |     |

---

#### 第二步：执行选择操作 $$ \sigma_{A \ge 3}(R \bowtie S) $$
从连接结果中筛选出满足 \( A \ge 3 \) 的元组：
- (4, b, 2)：$( A=4 \ge 3 )$，保留；
- (2, c, 3)：\( A=2 < 3 \)，舍弃；
- (3, e, 3)：$( A=3 \ge 3 )$，保留；
- (2, e, 3)：\( A=2 < 3 \)，舍弃。

---

### 最终结果 \( R1 \)
$$
R1 = \sigma_{A \ge 3}(R \bowtie S) = \begin{array}{|c|c|c|}
\hline
A & B & C \\
\hline
4 & b & 2 \\
3 & e & 3 \\
\hline
\end{array}
$$

```sql
-- 创建SC表，满足所有完整性约束
CREATE TABLE SC (
    -- 字段定义
    Sno CHAR(9) NOT NULL,  -- 学号，非空（主键字段必须非空）
    Cno CHAR(4) NOT NULL,  -- 课程号，非空（主键字段必须非空）
    Grade SMALLINT,        -- 成绩，整型
    
    -- ① 定义联合主码（Sno+Cno唯一标识一条选课记录）
    PRIMARY KEY (Sno, Cno),
    
    -- ② 定义参照完整性（外键约束）
    FOREIGN KEY (Sno) REFERENCES Student(Sno),  -- Sno关联学生表的主键
    FOREIGN KEY (Cno) REFERENCES Course(Cno),   -- Cno关联课程表的主键
    
    -- ③ 成绩范围约束（100 ≥ Grade ≥ 0）
    CHECK (Grade >= 0 AND Grade <= 100)
);
```
