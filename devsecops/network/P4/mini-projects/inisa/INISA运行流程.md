## 🎯 初始设置

- **h1**：训练节点，本地缓冲队列初始为空
- **h2**：存储节点，收到指令后固定延迟 3 秒再发送数据
- **控制平面**：初始 `T_comp_hat = 5s`，`T_load_hat = 3s`，所以初始 `D = ceil(3/5) + 1 = 2`

---

## 🕐 时间线

### T=0s —— 系统冷启动

h1 本地队列为空，无法取数据。

> **h1 主动发 READ 请求**：`"请给我编号 1"`（这是冷启动兜底）

---

### T=0.5s —— READ 到达 h2

h2 收到 READ，开始准备编号 1。

> （h2 模拟存储延迟，sleep 3s）

---

### T=3.5s —— 编号 1 到达 h1

h2 把编号 1 推送到 h1 的缓冲端口。

h1 的后台线程收到，**放入本地队列**。

h1 主循环从队列取出编号 1，**开始第一次模拟训练**。

> h1 随机抽到 `T_comp = 4s`，开始 sleep(4)

---

### T=7.5s —— 第一次训练完成，发 STATUS

h1 计算完成，构造 STATUS 报文：

> `<T_comp=4, BatchID=1>`

发送给 P4 交换机。

P4 交换机：

- 正常转发 STATUS
- **镜像一份给控制平面**

---

### T=7.6s —— 控制平面收到 STATUS

控制平面提取信息：

```
A = 1
T_comp = 4s
```

**更新 EWMA**：

```
T_comp_hat = 0.3×4 + 0.7×5 = 4.7s
T_load_hat = 3s（本次还没收到新 RTT，沿用初始值）
```

**计算预取深度**：

```
D = ceil(3 / 4.7) + 1 = ceil(0.64) + 1 = 1 + 1 = 2
```

**确定要推送的编号**：

```
A+1 到 A+D → 2, 3
```

控制平面构造 PREFETCH 指令：`<编号 2>`, `<编号 3>`，发送给 h2。

> 同时记录发送时间戳，用于后续 RTT 测量。

---

### T=7.7s —— h2 收到 PREFETCH(2) 和 PREFETCH(3)

h2 对每个 PREFETCH **立刻回复 ACK** 给控制平面。

> （ACK 用于控制平面独立测量 RTT）

然后 h2 开始模拟存储延迟（sleep 3s），准备数据。

---

### T=8.0s —— 控制平面收到 ACK

控制平面计算 RTT：

```
RTT = 8.0 - 7.6 = 0.4s（这只是网络RTT，不等同于 T_load）
```

这里要注意：`T_load` 是**从发出 PREFETCH 到数据到达 h1 的总时间**，不是 ACK 的时间。所以控制平面实际测量的 `T_load_real` 要等到数据到达 h1 的确认才能知道。

> 在 demo 里如果简化，可以假设 `T_load = h2 固定 3s + 网络 RTT 0.4s ≈ 3.4s`，或者在 h1 收到数据时再回一个确认。

---

### T=10.7s —— 编号 2 和编号 3 到达 h1

h2 的 3s 延迟结束，**批量推送**编号 2 和编号 3 到 h1 的缓冲端口。

h1 后台线程依次收到，**放入本地队列**。

此时队列状态：

```
[2, 3]
```

而在此之间，h1 主循环在 T=7.5s 发完 STATUS 后，**已经回到步骤1**，尝试从队列取数据。

> 但注意：从 T=7.5s 到 T=10.7s，队列是空的，h1 主循环**阻塞等待了约 3.2s**。

---

### T=10.7s —— h1 取到编号 2，开始第二次训练

h1 从队列取出编号 2。

> 随机抽到 `T_comp = 6s`，开始 sleep(6)

---

### T=16.7s —— 第二次训练完成，发 STATUS

h1 发送 STATUS：

> `<T_comp=6, BatchID=2>`

P4 交换机镜像给控制平面。

---

### T=16.8s —— 控制平面收到 STATUS(2)

```
A = 2
T_comp = 6s
```

**更新 EWMA**：

```
T_comp_hat = 0.3×6 + 0.7×4.7 = 5.09s
```

假设控制平面此时已经通过某种方式测得 `T_load_real ≈ 3.4s`：

```
T_load_hat = 0.3×3.4 + 0.7×3.0 = 3.12s
```

**计算预取深度**：

```
D = ceil(3.12 / 5.09) + 1 = ceil(0.61) + 1 = 2
```

**确定要推送的编号**：

```
A+1 到 A+D → 3, 4
```

但编号 3 已经在 T=7.6s 时预取过了（控制平面维护了 `S_prefetch = {2,3}`），所以**跳过 3**。

> 只发 PREFETCH(4) 给 h2。

---

### T=16.9s —— h2 收到 PREFETCH(4)

回 ACK，开始 3s 延迟。

---

### T=19.9s —— 编号 4 到达 h1

h1 队列现在：

```
[3]  ← 之前还没被取走的
[4]  ← 刚到的
```

> 注意：h1 在 T=16.7s 发完 STATUS(2) 后，立刻去取编号 3，取到了！所以**没有等待**。

---

### T=16.7s —— h1 取到编号 3，开始第三次训练

不等 4 到达，队列里已经有 3。

> 随机 `T_comp = 2s`（突然变快了！）

---

### T=18.7s —— 第三次训练完成，发 STATUS

h1 发送 STATUS：

> `<T_comp=2, BatchID=3>`

---

### T=18.8s —— 控制平面收到 STATUS(3)

```
A = 3
T_comp = 2s
```

**更新 EWMA**：

```
T_comp_hat = 0.3×2 + 0.7×5.09 = 4.16s
```

**计算 D**：

```
D = ceil(3.12 / 4.16) + 1 = ceil(0.75) + 1 = 2
```

**要推**：4, 5
**4 已预取**，只发 PREFETCH(5)。

---

### T=18.9s —— h2 收到 PREFETCH(5)

回 ACK，3s 延迟。

---

### T=21.9s —— 编号 5 到达 h1

队列：

```
[4]  ← T=19.9s 到的
[5]  ← 刚到
```

---

### T=18.7s —— h1 取到编号 4（队列里已有）

> 随机 `T_comp = 8s`

---

### T=26.7s —— 发 STATUS(4)，控制平面更新，推 5,6…

---

## 📊 从时间线里能看出什么

| 迭代编号 | h1 取数据时 | 队列状态   | 是否等待         | 等待时间 |
| ---- | ------- | ------ | ------------ | ---- |
| 1    | T=3.5s  | 空→取到   | ✅ 冷启动等了 3.5s | 3.5s |
| 2    | T=10.7s | 空→取到   | ✅ 等了 3.2s    | 3.2s |
| 3    | T=16.7s | 已有 [3] | ❌ 立即取到       | 0    |
| 4    | T=18.7s | 已有 [4] | ❌ 立即取到       | 0    |
| 5    | T=26.7s | 已有 [5] | ❌ 立即取到       | 0    |

**前两轮是预热期，之后 h1 永远从本地队列直接拿到数据，存储延迟完全被隐藏。**
