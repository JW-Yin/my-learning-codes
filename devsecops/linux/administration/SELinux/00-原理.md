# 0. 一句话总纲
**SELinux = 给 Linux 额外套一层「MAC 强制访问控制」**
在传统 UGO/DAC 权限之上再加一道**系统级铁锁**，从根源解决「权限一破、全系统失守」的问题。

---

# 1. 先回到根源：DAC（UGO）到底哪里不行？
DAC = 自主访问控制，靠 **UID/GID + 文件权限** 控制
它的 3 个致命漏洞：
1. **权限按用户绑定**
   拿到某个用户身份 = 拥有该用户**所有权限**
2. **root 完全不受限**
   UID=0 内核特殊对待，可读写删任何文件，无任何约束
3. **无行为边界、无进程隔离**
   攻陷一个服务 → 拿到相应用户 → 可横向渗透、乱访问、乱操作
→ **一点破，全局崩**

---

# 2. 解决方案：MAC（强制访问控制）
与 DAC 完全相反：
- DAC：**谁创建谁说了算，用户自主控制**
- MAC：**系统强制定规则，谁都不能越界（包括 root 进程）**

**SELinux 就是 Linux 内核里最成熟的 MAC 实现。**

---

# 3. SELinux 核心工作原理（最关键 4 点）
## ① 给所有东西贴「安全标签」= 安全上下文
格式：`user:role:type:level`
**99% 决策只看第三个：type（类型）**
- 进程的 type → 叫 **domain（域/牢笼）**
  例：`httpd_t`（Apache）、`sshd_t`、`mysqld_t`
- 文件的 type → 叫 **type（类型）**
  例：`httpd_sys_content_t`（网页）、`shadow_t`（密码）

## ② 核心机制：类型强制 TE（Type Enforcement）
只认标签，不认人/UID。
规则格式：
```
allow 进程域 文件类型 : 对象类型 { 权限 };
```
**只允许规则写死的行为，除此之外默认全部拒绝。**

## ③ 双层检查：先 DAC，再 SELinux
任何访问必须：
```
DAC 权限通过 → SELinux 策略通过 → 才允许
```
一道不通过，直接拒绝。

## ④ 进程强隔离：每个服务一个独立“监狱”
- Apache 关在 `httpd_t`
- MySQL 关在 `mysqld_t`
- 不同域**默认互不可访问**
→ 攻陷一个服务 = 只能在小盒子里，无法横向扩散

---

# 4. SELinux 三种模式（必须知道）
1. **enforcing（强制）**
   拦截违规 + 记日志（生产默认）
2. **permissive（宽容）**
   不拦截，只记日志（调试用）
3. **disabled（关闭）**
   完全不工作（不推荐）

---

# 5. 为什么它能真正防住攻击？（你理解的完全正确）
1. **最小权限**：进程只能做策略允许的极少操作
2. **权限不随用户走**：服务进程即使 UID=0 也被锁死
3. **阻断横向渗透**：服务之间互相隔离
4. **全行为审计**：所有违规写入 `/var/log/audit/audit.log`
→ **拿到进程 ≠ 拿到系统**

---

# 6. 极简对比：DAC vs SELinux(MAC)
| 维度         | DAC（UGO）                  | SELinux（MAC）               |
|------------|----------------------------|------------------------------|
| 控制依据      | UID、文件权限               | 安全标签 + 强制规则           |
| 权限归属      | 用户自主控制                | 系统强制控制                 |
| root 地位    | 上帝，无视一切              | 进程仍受 domain 限制          |
| 隔离能力     | 弱，易横向渗透              | 强，服务互相隔离              |
| 默认策略     | 默认允许                    | 默认拒绝                     |

---

# 7. 最终一句话记忆
**DAC 管「你是谁」，SELinux 管「你能做什么」。
双层防护，锁死行为，从根源防止权限扩散。**
