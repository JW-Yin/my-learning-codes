# 第2章 基础设施：网络与存储 【提前植入，为后续铺路】
> 本章在深入学习容器命令之前，先将网络和存储的核心概念解释清楚，避免后续章节的 “先使用后理解”。

### 2.1 Docker 网络基础
#### 2.1.1 四种网络驱动速览
- **关键词**：`bridge`（单机默认）、`host`、`none`、`overlay`（Swarm 场景简介）。
#### 2.1.2 自定义桥接网络与服务发现
- **核心机制**：创建自定义 `bridge` 网络后，容器名/服务名自动作为 DNS 名称。
- **演示**：用网络操作的简单命令（如 `docker network create`、`docker run --network`）展示，但不深入讲解 `docker run` 其他参数。
#### 2.1.3 端口映射预览
- **概念**：`-p 宿主机端口:容器端口` 的作用，浅提 iptables DNAT（详见第7章）。
#### 2.1.4 容器间通信最佳实践
- **要点**：摒弃 `--link`，统一使用自定义网络。

### 2.2 Docker 存储方案
#### 2.2.1 Volume：持久化与数据管理
- **关键词**：Docker 管理的存储（`/var/lib/docker/volumes`）、命名卷与匿名卷、`docker volume` 子命令。
- **生命周期**：独立于容器，需手动删除。
#### 2.2.2 Bind Mount：开发热更新利器
- **关键词**：宿主机绝对路径挂载、实时同步、权限（SELinux/用户映射）。
#### 2.2.3 tmpfs：非持久内存存储
- **场景**：敏感信息、临时高速缓存。
#### 2.2.4 挂载行为快速决策表
- **对比卡片**：Volume（持久、方便备份） vs Bind Mount（开发同步） vs tmpfs（性能、临时）。

- **命令**：`docker run -d --name web -p 8080:80 -v mydata:/app -e KEY=val --rm -it`。

# 第4章 Dockerfile 专家实践 【重点，面试手写高频】
### 4.1 指令解析与层缓存优化
#### 4.1.1 FROM, WORKDIR, COPY, ADD 与 EXPOSE
- **要点**：COPY 优先于 ADD，WORKDIR 免路径漂移。
- **EXPOSE**：仅声明元数据，不起实际端口映射作用（对比 `-p` 的参数映射）。
#### 4.1.2 RUN 与缓存失效
- **技巧**：合并 RUN 指令（`&&`）、清理包缓存、变更少的指令前置。
#### 4.1.3 CMD 与 ENTRYPOINT 的组合艺术
- ** exec 格式 vs shell 格式**：ENTRYPOINT 固定执行器，CMD 提供默认参数。

### 4.2 多阶段构建与镜像瘦身
#### 4.2.1 多阶段语法与案例
- **关键词**：`FROM ... AS builder`、`COPY --from=builder`、Go/Node 多阶段实战。
#### 4.2.2 基础镜像选型策略
- **对比**：`alpine`、`distroless`、`slim` 的安全与体积权衡。

### 4.3 构建优化与最佳实践
