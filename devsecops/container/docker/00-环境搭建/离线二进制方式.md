# Docker 引擎 + 传统独立版 docker-compose（横杠版）


### 1. 核心思路（一次讲透）
- **在联网机器上完成所有“解压”工作**，最终交付给目标服务器的，应该是一堆**裸二进制文件 + 一份部署脚本**。
- 安装路径仍遵循最佳实践：全部放入 `/usr/local/bin`。

### 2. 联网端准备工作（你只需做一次）
在你能上网的电脑上，创建项目文件夹并收集所有材料。

```bash
# 创建工程文件夹并进入
mkdir -p ~/docker-offline-kit
cd ~/docker-offline-kit

# 1. 下载 Docker 引擎静态包
wget https://mirrors.tuna.tsinghua.edu.cn/docker-ce/linux/static/stable/x86_64/docker-29.4.3.tgz

# 2. 下载 docker-compose 独立二进制
wget https://github.com/docker/compose/releases/download/v2.24.0/docker-compose-linux-x86_64

tar -xzf docker-29.4.3.tgz
# 现在会出现一个 docker/ 目录，里面就是所有二进制文件
ls docker/
# 应该看到：docker  dockerd  docker-init  docker-proxy  containerd  containerd-shim-runc-v2  ctr  runc

# 3. 把 docker-compose 也放进去（方便统一管理）
cp docker-compose-linux-x86_64 docker/docker-compose

# 4. 给 docker-compose 执行权限（可选，反正目标机器会统一加）
chmod +x docker/docker-compose

```

现在你的 `docker-offline-kit/` 目录结构如下：
```
docker-offline-kit/
├── docker-29.4.3.tgz         (保留，以后备用)
├── docker-compose-linux-x86_64
└── docker/                   (★ 这就是我们真正要带去离线机器的“弹药”)
    ├── docker
    ├── dockerd
    ├── docker-init
    ├── docker-proxy
    ├── containerd
    ├── containerd-shim-runc-v2
    ├── ctr
    ├── runc
    └── docker-compose
```

**将整个 `docker/` 文件夹拷贝到 U 盘（或通过内网 SCP 传输到目标服务器）。**

### 3. 离线目标服务器部署步骤（完全无需 `tar`）

假设 U 盘挂载后，你的 `docker/` 文件夹被复制到了目标服务器上的 `/home/rocky/docker/` 目录。

#### 3.1 复制二进制文件到系统路径
```bash
cd /home/rocky/docker

# 1. 给所有二进制文件一次性加上可执行权限
sudo chmod +x *

# 2. 使用 cp -p 保留权限，一步到位复制到 /usr/local/bin
sudo cp -p * /usr/local/bin/
```

#### 3.2 验证二进制可用
```bash
/usr/local/bin/docker --version
/usr/local/bin/docker-compose --version
```

#### 3.3 创建 systemd 服务（离线优化版，直接粘贴）
```bash
sudo tee /etc/systemd/system/docker.service <<-'EOF'
[Unit]
Description=Docker Application Container Engine
After=network.target
Wants=network.target

[Service]
Type=notify
ExecStart=/usr/local/bin/dockerd
ExecReload=/bin/kill -s HUP $MAINPID
LimitNOFILE=infinity
LimitNPROC=infinity
LimitCORE=infinity
TimeoutStartSec=0
Delegate=yes
KillMode=process
Restart=on-failure
StartLimitBurst=3
StartLimitInterval=60s

[Install]
WantedBy=multi-user.target
EOF
```

#### 3.4 启动 Docker 并设置自启
```bash
sudo systemctl daemon-reload
sudo systemctl start docker
sudo systemctl enable docker.service
sudo systemctl status docker   # 确认 active (running)
```

#### 3.5 永久解决普通用户 Docker 权限问题
```bash
sudo groupadd docker 2>/dev/null || true
sudo usermod -aG docker $USER

sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json <<-'EOF'
{
  "group": "docker"
}
EOF

sudo systemctl restart docker
```

#### 3.6 重新登录使组权限生效
```bash
exit          # 退出当前SSH
# 重新连接后测试：
docker ps     # 未报权限错误则完美
docker-compose version
```
好，我们把 `alpine:latest` 镜像测试环节正式加入最终方案里。

## 补充测试环节：用 alpine 镜像全面验证 Docker 功能

这个环节可单独执行，无需依赖其他应用镜像，能更深层地验证容器运行、交互、后台驻留等核心能力。

### 1. 联网端准备（只需做一次）
```bash
docker pull alpine:latest
docker save -o alpine.tar alpine:latest
```
把生成的 `alpine.tar`（约 14 MB）通过 U 盘传到离线服务器的任意目录，比如 `/home/rocky/`。

### 2. 离线端导入镜像
```bash
docker load -i alpine.tar
```

### 3. 执行三层测试

**① 快速运行测试（验证容器创建和命令执行）**
```bash
docker run --rm alpine echo "Docker is working!"
```
预期输出：`Docker is working!`

**② 交互式 Shell 测试（验证文件系统、权限、进程隔离）**
```bash
docker run -it --rm alpine /bin/sh
```
进入后可以尝试：
```sh
ls /
cat /etc/os-release
exit
```

**③ 后台驻留与 exec 测试（模拟应用持续运行场景）**
```bash
docker run -d --name alpine-test alpine tail -f /dev/null   # 保持运行
docker ps                                                   # 应看到 alpine-test
docker exec alpine-test echo "hello from inside"            # 输出 hello from inside
docker stop alpine-test && docker rm alpine-test            # 清理
```

### 4. 结果判定
- 如果以上三项全部成功，说明你的离线 Docker 环境已具备完整的容器生命周期管理能力，可以放心运行任何你未来导入的应用镜像。
- 如果某项失败，请提供报错信息，我们再针对性排查。

### 七、未来维护备忘
- **升级引擎**：下载新版 `.tgz`，解压覆盖 `/usr/local/bin/` 中的文件，重启 `docker.service` 即可。
- **升级 compose**：下载新二进制文件，替换 `/usr/local/bin/docker-compose` 并赋予执行权限。
- **新增镜像**：每次需要新镜像时，在联网机器上 `docker save` 打包，再到离线端 `docker load` 导入。
